# 인증 만료 응답 순서 검사 · PT-114 U3

99b6516의 UI CI45960918610 첫 실행에서 테스트 쿠키 삭제 후 홈의 방 참여 링크를
클릭하기 전에 DOM이 사라져30초 timeout했다. 동일 SHA 재실행은 성공했으며 최초 실패는
Jira10885에 보존한다. 제품의 인증 차단 실패나 내부 이벤트 순서가 확정된 증거는 아니다.

HomePage는 참여 수업·복습 외에 종료 수업(`/api/sessions/ended`)도 조회한다.
기존 검사는 앞의 두 조회만 합성200으로 제어해 종료 수업 조회가 쿠키 삭제 뒤401을 받고
참여 링크 클릭보다 먼저 로그인 상태를 정리할 수 있었다.

`tests/e2e/auth-recovery.spec.js`에서 다음 두 순서를 별도로 검증한다.

| 순서 | 제어 및 실제 관측 |
| --- | --- |
| 명시적 참여 | 홈 조회3개는 합성200. 격리 앱 쿠키 삭제 후 링크·코드·입장 흐름을 실행하고 실제 Spring 참여 POST의401, 로그인 만료 안내와 메인 메뉴 제거를 요구한다. |
| 늦은 홈 조회 | 종료 수업 요청을 gate에서 보류한다. 요청 진입·로그인 완료 후 격리 쿠키를 지우고 gate를 해제한다. 실제 bridge/Spring의 GET401과 클릭 없는 로그인 만료 전환을 요구한다. 실패 시에도 gate를 해제해 정리를 막지 않는다. |

응답 path·method·status·사례만 `auth-expiry-boundary.json` 파일로 저장해 첨부한다.
쿠키·원문 URL·사용자 화면 데이터는 기록하지 않는다. 401 응답은 합성하지 않는다.
제품 코드·세션/CSRF 정책·본문60초/expect10초·자동retry0은 유지하며 sleep을 추가하지 않는다.

고정 Node/Electron/Java와 일회용 PostgreSQL·실제 Spring을 준비한 기존 UI CI에서
전체 사례를 실행한다. 해당 환경의 반복 확인은
`npm run test:e2e -- auth-recovery.spec.js --repeat-each=3`으로 실행할 수 있다.
`--list` 출력은 수집 확인이며 실제 기능 통과로 집계하지 않는다.
로컬 테스트 서버는 전용 DB guard를 유지하고 운영/팀 DB를 사용하지 않는다.
실계정 OAuth·운영 서버·설치 앱 인수와 별도다. 실행 수·시각·SHA·실패/성공은 Jira에 기록한다.
