# TUTIPAL 운영 정책서 (세션 시간 · 접속 기기 · 기록 보관)

- WBS 15행 "운영 정책 결정" 산출물 · 결정 카드 [PT-13](https://gad03302.atlassian.net/browse/PT-13)
- 기준: develop `b50079d` (2026-11-26) 코드 기본값과 Jira 결정 댓글
- 작성: PL·PM 전설민 · **상태: 초안 (PM 확정 전)**

이 문서는 운영에서 바뀔 수 있는 값을 한곳에 모은다. 각 항목의 **상태**는 다음 뜻이다.

| 상태 | 뜻 |
| --- | --- |
| 확정 | Jira 결정 기록이 있다. 바꾸려면 새 결정 기록이 필요하다 |
| 제안 | 코드에 값이 들어가 있지만 결정 기록은 없다. PM이 확정하면 "확정"으로 바꾼다 |
| 미정 | 값도 결정도 없다 |

코드 기본값이 있다고 해서 확정 정책이 되지는 않는다 (PT-13 AC-DEC-001-3). 값은 모두 `tutipal_back/src/main/resources/application.yaml` 기준이며, 환경 변수가 있는 항목은 운영 `.env.prod`로 바꿀 수 있다.

## 3. 기록 보관과 삭제

| 데이터 | 현재 동작 | 설정 | 상태 | 근거·결정 위치 |
| --- | --- | --- | --- | --- |
| 화면 원본(캡처 이미지) | 저장하지 않음. 로그·임시 파일에도 남기지 않음 | — | 확정 | 설계 §13, PT-13 2026-11-23 |
| 복습 기록(분석 요약·학습 시간) | 본인 조회·개별/전체 삭제. 자동 삭제 없음 | — | 제안 | 추천 기준: 최근 7일 3회 또는 10분, 같은 묶음 하루 1회 (`ReviewService`) |
| AI 대화·요약·기억 | 사용자가 지우거나 탈퇴할 때까지 보관 | `app.ai.conversations.retention-days: 0`(자동 삭제 끔) | 제안 | PT-106. 단기 기억=시간·토큰, 장기 기억=중요도·유효성 방향(PT-13 댓글 10402) |
| 사용자가 지운 AI 대화 | 30일 뒤 물리 삭제 | `deleted-purge-days: 30` | 제안 | PT-106 soft delete |
| 학생 질문 원문(개념 분석용) | 30일 뒤 삭제 | `app.insights.questions.retention: 30d` | 제안 | PT-87 |
| 집중도 체크 기록 | 수업 종료 30일이 지난 기록, 그리고 수업 종료와 상관없이 31일이 지난 기록을 매시간 배치로 삭제. 동의한 학생만 | `app.focus.retention-days: 30`, `max-sample-age-days: 31` | 제안 | PT-90 (PM 확인 대기: 31일 상한) |
| 교사↔학생 도움 채팅 | 저장함. 회원 탈퇴·수업 삭제 시 함께 삭제. 일반 보관 기간은 없음 | — | 확정(일부) | PT-13 댓글 10391·10413. 자동 삭제 주기는 미정 |
| 답안·게시글·자료 파일 | 수업이 남아 있는 동안 보관 | — | 미정 | NFR-PRV-02 |
| 회원 탈퇴 | 계정과 개인 기록을 **즉시 삭제**. 내가 연 수업은 그 안의 다른 학생 기록까지 함께 삭제 | `AccountCleanup` | 제안 | PT-13 댓글 10040 (임시 가정). 익명화·지연 삭제 여부 결정 필요 |
| 로그 | 쿠키·JWT·비밀키·화면 이미지·대화 원문을 남기지 않음 | — | 확정 | 설계 §13 |

자동 삭제 기간은 "그 기간이 지나면 삭제 대상이 된다"는 뜻이다. 실제 삭제는 주기 배치(집중도·지운 AI 대화 매시간, 질문 원문 `cleanup-interval: 1h`)가 하므로 정상 실행 시 보통 한 주기 안에 지워진다. 배치는 고정 지연으로 예약되고 실패할 수 있어 상한은 보장하지 않으며, 서버가 멈춰 있던 동안 쌓인 대상은 재기동 뒤 첫 배치에서 지운다. 정확한 시각 보장이 필요하면 조회 시점 필터를 따로 둬야 한다.

## 4. 사용량 제한 (참고)

AI 호출 한도는 PT-97에서 구현했다. 아래는 임시값이며 정책 승인을 기다린다 (`app.ai.quota`, 사용자 × 기능별 1시간 슬라이딩 윈도, 서버 메모리).

| 기능 | 1시간 한도 | 상태 |
| --- | --- | --- |
| 화면 자동 분석 | 120 | 제안 |
| 화면 수동 분석 | 30 | 제안 |
| AI 채팅 | 60 | 제안 |
| 문항 생성 | 20 | 제안 |
| 개념 분석 | 10 | 제안 |
| 서버 전체 동시 AI 요청 | 2 (`AI_MAX_CONCURRENT`) | 제안 |
| 업로드 파일 크기 | 10MB | 제안 |
| 수업 초대 코드 실패 | 계정당 5분에 5회 (서버 메모리, `InviteCodeJoinService` 상수) | 제안 |

수업 초대 코드 제한은 PT-98(최진우)에서 구현했으며 값은 설정 파일이 아니라 코드 상수다.

## 5. PM 확정이 필요한 결정

아래 다섯 가지가 정해지면 해당 행의 상태를 "확정"으로 바꾸고 PT-13에 결정 댓글을 남긴다.

1. **동시 로그인 기기 수**: 제한 없음(현행) / 1대(새 로그인이 이전 기기를 끊음) / 1대(새 로그인 거절)
2. **회원 탈퇴 처리**: 즉시 삭제(현행) / 내 기록은 삭제하고 다른 학생 기록이 있는 수업은 익명화
3. **AI 대화 보관 기간**: 사용자 삭제까지(현행, 0) / N일 뒤 자동 삭제
4. **임시 30일 값**(질문 원문·삭제 유예·집중도) 그대로 확정 여부
5. **AI 호출 한도·업로드 크기·초대 코드 실패 제한** 임시값 확정 여부
