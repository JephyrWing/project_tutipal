# 화면 공유 종료·재접속 검사 (PT-46 U1)

기준: TUTIPAL-baseline-v2 / jira_drive-v3, FR-SHR-01·04·06 / NFR-SEC-04.
이 단위는 PR #18(PT-58)의 동의·선택 목록·판서 초기화 수정에 이어지는 변경이다.
PR #18을 먼저 develop에 통합한 뒤 이 PR의 후속 diff를 확인한다.
PR 제출, 검사, develop 병합, PM 직접 확인은 각각 별도로 기록한다.

## 구현 동작

- 시그널링만 복구할 때 상태를 안내하고, 미디어 자체의 재접속 시 캡처를 중지한다.
- SDK가 연결을 복구해도 자동으로 화면을 다시 캡처하지 않는다. 학생은 새 동의와 시작을 거친다.
- 연결이 완전히 끝나면 `다시 연결`로 새로운 Spring 입장 승인을 요청한다.
  로그아웃·퇴장·종료된 방/도움 요청의 거절을 우회하지 않는다.
- 공유 준비 중 화면 이동·중지·끊김이 발생하면 나중에 생성된 트랙도 중지한다.
  같은 participant의 이전 캡처 정리가 끝나기 전에는 새 캡처를 시작하지 않는다.
- OS 공유 중지·창 닫힘의 트랙 종료 시 미리보기와 공유 표시를 정리한다.
- 오래된 영상의 구독 해제가 새 영상을 지우지 않도록 현재 트랙을 대조한다.

## 자동 검사

Node 24.22.3, `tutipal_front`에서:

```powershell
node --test tests/*.test.mjs
npm.cmd run check
npm.cmd run build
```

Node 검사는 API/LiveKit/캡처 경계를 대체한 상태·경합 검사다. 실제 미디어나 서버 권한 검사가 아니다.
신규 `liveRoomSession.test.mjs` 7개와 `screenShareSession.test.mjs` 10개,
PR #18에서 보존한 기존 검사 17개를 실행한다. 현재 합계는 34개다.
`.github/workflows/front-share-tests.yml`은 PR에서 같은 Node 검사를 실행한다.
빌드 성공이나 합성 Electron UI 확인 수를 이 34개에 더하지 않는다.
학생 캡처의 실제 호출 경로는 `screenShareSession`이며 이전 `helpScreenShare` helper는
PR #18 보호 범위와 기존 증거를 보존하기 위해 남겨 두었다.

## 실제 앱 인수 절차 (별도 실행 필요)

1. 개인 개발 환경에서 서로 다른 교사·학생 프로필로 같은 방에 접속한다.
2. 교사가 직접 선택한 합성 테스트 창을 공유한다. 학생 LIVE와 교사 미리보기를 확인한다.
3. 공유를 중지하거나 테스트 창을 닫는다. 양쪽 영상과 공유 표시가 사라지는지 확인한다.
4. 일시적인 네트워크 단절 후 복구한다. 연결 복구 안내와 캡처 중지,
   학생 재동의/명시 시작 전 영상 재전송이 없는지 확인한다.
5. 완전 종료 뒤 `다시 연결`을 누른다. 새로운 Spring 승인과 중복 접속 부재를 확인한다.
6. 도움 종료·로그아웃·세션 종료·내보내기 후 재시도한다. 승인 거절과 캡처 정리를 확인한다.
7. 공유 선택 대기 중 탭 이동/로그아웃을 반복한다. 늦게 생성된 캡처가 남지 않아야 한다.

실제 장비·네트워크·앱 SHA·환경·시각·관측 결과는 PT-65/PT-19에 기록한다.
원화면·쿠키·JWT·실제 env는 증거에 넣지 않는다.

## 남은 차이

학생 도움 공유는 현재 주 모니터 전체를 명시 동의하는 방식이다.
FR-SHR-04의 학생 창 선택·시작 전 미리보기 전체 AC는 충족했다고 표시하지 않는다.
임의 창/다른 모니터와 주 모니터 오버레이의 좌표 매핑은 PT-48과 조율이 필요하다.
외부 두 장비 WebRTC/TURN(PT-19), 실계정 OAuth와 서버 강제 퇴장(PT-14/59),
패키징·다른 OS·운영 배포도 이 상태 검사로 대체하지 않는다.
중앙 검사/설계 파생 문서 반영은 같은 Jira 원작업의 docs-sync-pending으로 인계한다.
