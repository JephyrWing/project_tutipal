# PT-124 개인 기본 챗봇 저장 연결 U1

요구 FR-TUT-05 / PT-124. 기준 develop `99b6516cdcc01fb5e96c62cd924022028c804d7b`.
개인 `/chat`만 기존 PT-106 저장 대화 API에 연결한다. 수업용 export ChatPanel 함수,
수업 화면·위젯·화면 요약·PT-85/PT-102 계약·서버·DB·배포 설정은 변경하지 않는다.

## 동작

- 첫 질문에서 개인 대화를 만들고 같은 ID의 messages API로 전송한다. 질문마다 UUID를 발급하고
  저장 확인 전 실패/중지 후 같은 글을 재시도하면 같은 UUID를 쓴다. 저장 확인이 유실돼도 서버의 재생 계약으로 중복 쌍을 만들지 않는다.
- 질문·답변은 saved 이벤트로 저장 확인 후 완료 표시한다. ‘이 대화 기록 열기’는 해당 ID 상세로 이동하며 이후 질문도 같은 저장 이력을 사용한다.
- 전송 중 중복 제출을 ref로 막는다. 중지는 즉시 입력을 복원하고 부분 답변을 제거한다. 이전 요청은 취소하고 늦은 결과가 새 요청 상태를 바꾸지 못하게 한다.
- 중지/보내기 버튼은 별도 key와 기본 동작 취소를 사용한다. DOM 버튼 교체가 중지 클릭을 폼 재제출로 이어가지 않도록 한다.
- 대화 생성 응답이 늦어도 같은 화면의 중지·재시도는 생성 Promise를 재사용한다. 생성 도중 중지하면 질문은 자동 전송하지 않는다.
- 계정/주제가 바뀌면 개인 컴포넌트를 새로 만들고 이전 요청을 무효화한다. ID·입력·대화 내용은 전역/localStorage에 두지 않는다. 404 응답이면 기존 화면 내용/기록 링크를 비우고 전송을 막는다.
- 저장은 기존 보관 정책을 따른다. saved 보존 토글을 자동으로 켜지 않는다. 기존 자동 요약/기억 저장 정책을 변경하지 않는다.

## 검사

`tutipal_front`에서 `npm run check`, `npm run build`, `node --test tests/*.test.mjs`.

- `node tests/personal-stored-chat-ui.mjs`: 실제 Electron/Main/preload와 메모리 모의 저장 HTTP 서버.
  동일 ID 기록 재개·동시 제출 잠금, saved 유실 재시도, 503 재시도, 중지와 재전송 방지, 계정 격리 5개 기능군. 실제 DB/모델 검사가 아니다.
- `npm run test:e2e -- personal-stored-chat.spec.js`: 실제 Spring·폐기용 PostgreSQL·모의 AI.
  저장·기록 재개/재조회, 중복 제출, 실제 저장 후 saved 응답만 유실시켜 같은 키로 재생,
  503/보류 응답을 주입한 재시도·중지·계정 전환, 생성 응답 보류 후 중지/동일 생성 재사용 4사례.
  CI front-e2e가 다른 기존 사례와 함께 자동 수집한다. 기존 fixture/helper는 변경하지 않는다.

초기 모의 UI에서 중지 뒤 입력 잠금이 재현됐다. 버튼 교체에 따른 재제출 경계를 막은 뒤 5개 기능군 통과.
실행 시각·최종 SHA·명령/종료 코드·최초 실패와 재검사·원격 CI는 Jira PT-124 원댓글에 기록한다.
로컬 Docker 엔진 미기동으로 로컬 실제 DB 검사는 실행하지 않으며 원격 CI의 실제 DB 결과와 분리한다.

## 잔여와 한계

개인 U1만 완료 대상으로 삼는다. 수업·위젯 저장 연결과 과거 자료 출처/도움 추천 저장·복원은 제외한다.
실 모델 품질·실 OAuth·운영 배포는 검증하지 않는다. 화면 새로고침/새 진입은 새 개인 대화를 시작하며 이전 대화는 기록에서 연다.
대화 생성 응답이 네트워크에서 완전히 유실된 경우 기존 생성 API에 멱등 키가 없으므로 빈 대화가 남을 수 있다.
이번 범위에서 공통 생성 API를 바꾸거나 저장 성공/환불을 추정하지 않는다. 이미 서버가 저장한 뒤 중지된 턴은 기록 재조회/동일 키 재시도로 확인한다.
