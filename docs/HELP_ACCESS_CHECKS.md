# PT-65 개별 도움 접속 회수 통합검사

FR-SHR-04·06 / NFR-SEC-04 / AC-SHARE-001-3 중 Spring 접속 권한과 중계 연결 회수 부분을 검사한다.
제품 동작·API·DB·권한 정책을 변경하지 않는 검사 추가다.

## 실행 환경과 명령

Java 21, 저장소 지정 Node 24, 일회용 PostgreSQL/pgvector를 사용한다.
`tutipal_back`에서 `./gradlew bootJar --no-daemon`, `tutipal_front`에서 `npm ci` 후 `npm run test:help-access`를 실행한다.
`E2E_DB_URL`은 `jdbc:postgresql://127.0.0.1:25432/tutipal_e2e`, DB 사용자 `tutipal_e2e`,
`E2E_DB_PASSWORD`는 해당 일회용 DB 비밀번호여야 한다. 실제 `.env`나 팀 DB를 사용하지 않는다.
28080(Spring), 28081(기존 합성 AI), 28082(합성 LiveKit 제어 서버)를 비워 둔다.
CI `help-access` 작업은 DB 생성·최신 Flyway 적용·실행·보고·해당 컨테이너 종료를 담당한다.

## 실제 확인 범위

실제 Spring 서버의 HTTP 세션·CSRF·최신 스키마·권한 검사와 Java WebSocket 중계를 사용한다.
LiveKit 업스트림만 loopback 합성 HTTP/WS 서버다. 매 실행 생성한 비밀값으로 HS256 JWT 서명과
방·발행·구독·데이터 발행 금지 권한을 확인한다. 토큰·쿠키·접속 키 원문은 보고하지 않는다.

1. 미수락 도움과 제3자 접근 거절, 화면 발행 권한 제한, 도움 종료 뒤 기존 소켓 종료와 재접속 거절.
2. 로그아웃 뒤 소켓 회수, 같은 계정 재로그인 뒤 이전 로그인 세션 주소 재사용 거절, 새 주소 발급.
3. 학생 내보내기와 방 종료 뒤 소켓 회수·접속 거절.

각 회수는 실제 연결을 합성 문구 왕복으로 확인한 뒤 Spring의 소켓 종료와
`RemoveParticipant` 호출을 모두 기다린다. 합성 업스트림은 제거 요청을 받아도 소켓을 닫지 않으므로
Spring이 연결을 회수했는지 확인할 수 있다. 기본 대기 한도 12초는 검사 타임아웃이며 제품 지연 보장이 아니다.

JUnit XML의 실제 testcase/실패/건너뜀 수를 CI에서 집계한다. 실패·보고서 누락·실행 0건은 성공 처리하지 않는다.
서로 다른 실행과 빌드 성공 수를 기능 검사 통과 수에 합산하지 않는다.

## 별도 확인 대상

실제 LiveKit 프로토콜/미디어 호환성, 외부 두 장비·TURN(PT-19), 실제 화면 캡처,
재로그인 화면 동의 UI·혼합 DPI·다른 OS는 이 검사로 통과 처리하지 않는다.
검사의 `shareScreen` 값은 합성 요청 데이터이며 실제 사용자의 화면 공유 동의 증거가 아니다.
강제 퇴장 후 같은 코드 재입장 정책은 미확정이므로 이 검사에 새 기대값을 추가하지 않는다.
PT-65 전체 완료와 PM 인수는 별도다.
