# PT-96 개별 도움 채팅

FR-SHR-09의 구현 원본. 수락된 도움의 요청 학생과 **실제 수락한 교사**만 이용한다. 화면공유·동의·LiveKit 접속과 독립적으로 Spring HTTP로 전송하고, 기존 사용자별 STOMP 이벤트로 변경을 알린다. 클라이언트 SEND와 LiveKit data publish는 허용하지 않는다.

## 저장과 삭제

V19는 `help_chat_messages`와 `help_requests.accepted_by_user_id`, `next_chat_sequence`를 추가한다. 기존에 병합된 migration은 수정하지 않는다. 초안의 V17은 미병합 상태에서 다른 작업의 V18 이후에 적용되도록 V19로 조정했다. 기존 도움의 수락자를 현재 교사로 추정하지 않는다. 수락자가 기록되지 않은 기존 요청은 채팅 접근을 거절하며, 해당 도움을 종료하고 새로 요청·수락해야 한다. 기존 화면공유/판서 데이터는 변경하지 않는다.

메시지는 인증된 발신자·서버 시각·도움별 순번·UUID 전송 번호와 함께 저장된다. 도움별 순번과 (도움, 발신자, UUID)는 각각 고유하다. 동일 UUID/본문 재시도는 기존 결과를 반환하고, 다른 본문은 409다. 거절·종료 뒤 재시도는 기존 메시지가 있어도 먼저 접근을 거절한다.

회원 탈퇴는 PM 결정(2026-11-26, PT-13)에 따라 도움 요청과 메시지를 **지우지 않는다**(이전 PT-13/10413, PT-96/10414의 "탈퇴 시 함께 삭제"를 대체). 계정만 익명화되어 발신자 이름이 `탈퇴한 사용자`로 보이고, 탈퇴자의 열린 도움은 DONE으로 닫히며(이후 조회는 410), 탈퇴한 교사가 연 진행 중 수업은 종료된다. 수업 행이 지워지는 경우에만 도움/발신자 FK가 메시지를 연쇄 정리한다. 일반 보관 기간·주기적 삭제·운영자 원문 조회는 미정이며 이번 구현에 추가하지 않는다. **방 닫기/도움 종료는 물리 삭제가 아니라 접근 차단**이다. AI 단기/장기 기억 정책을 사람 간 채팅에 적용하지 않는다.

## HTTP 및 알림

- `POST /api/help/{helpId}/messages`: `{clientMessageId: UUID, text}`. 발신자·순번·시각은 서버가 결정한다. 응답은 `{id, helpId, sequence, senderId, clientMessageId, text, createdAt}`.
- `GET /api/help/{helpId}/messages?afterSequence=0&limit=100`: `{items, nextCursor, hasMore, maxLength}`. 마지막 반환 순번을 다음 커서로 사용하며 빈 페이지는 입력 커서를 유지한다. bigint ID/순번은 문자열이다.
- 입력 상한은 1000 Unicode code point, 조회는 페이지당 최대 100개다. 공백만 있는 입력을 거절하고 줄바꿈·한글을 보존한다. 렌더링은 React 텍스트 노드다.
- 로그인·CSRF는 기존 Spring 필터, 수업 참가/역할·활성 수업·ACCEPTED·수락 당사자는 Service에서 매번 검사한다. 당사자 외에는 404, 당사자의 종료된 도움은 410이다.
- 커밋 뒤 두 사용자에게만 `/user/queue/events`의 `{type: 'helpChat', id: helpId}`를 발행한다. 원문을 이벤트/수업 토픽/로그에 넣지 않는다. 페이지 조회는 다시 권한을 검사한다.

## 종료·동시성·복구

전송/조회와 도움 수락·종료는 수업 행 → 도움 행 순서로 잠근다. 학생 나가기·내보내기·수업 종료도 수업 행을 먼저 잠근다. 탈퇴는 먼저 자기 사용자 행을 `FOR NO KEY UPDATE`로 잠그고(도움 요청·수업 만들기·참가도 수업 행보다 먼저 같은 행을 `FOR SHARE`로 잠가 탈퇴 계정이면 401), 관련 수업 ID 오름차순으로 잠근 뒤 수업 종료·도움 종료·계정 익명화를 한다. 따라서 잠금 이후 종료/퇴장이 먼저 커밋됐다면 새 발송은 거절된다. 커밋 전에 승인되어 이미 전송된 데이터를 소급 회수한다고 보장하지 않는다.

앱은 도움/계정별 클라이언트를 생성하고 종료/언마운트 시 메모리·진행 중 요청을 정리한다. 개인 알림·재접속/포커스 변경에 조회하며, 누락 알림과 인증 만료는 5초 간격의 권한 있는 조회로 복구한다. 단일 HTTP 요청은 10초 후 취소한다. 조회 범위는 최대 100페이지이며 이를 초과하면 오류를 표시하고 커서를 전진시키지 않는다. 영속 outbox나 무제한 이력 탐색 UI는 구현하지 않았다.

## 검증 경계

`node --test tests/*.test.mjs`, `node tests/help-chat-ui.mjs`는 상태/React 합성 검사다. JUnit `HelpChatServiceTest`는 서비스 권한·입력·중복·알림 계약을 확인한다. `tests/e2e/help-chat.spec.js`는 기존 일회용 PostgreSQL/Flyway·Spring·sandbox Electron 환경에서 실제 API/화면을 검증한다. 자동 검사는 실제 팀 DB나 OAuth 계정을 사용하지 않는다. 실행 수·최종 SHA·실패/미실행·CI 링크는 Jira PT-96에 기록한다. 로컬 팀 DB/설치본 적용·운영 배포·PM 최종 완료는 별도다.
