자료구조와 알고리즘 강의 노트 - 정렬과 탐색
(팀 작성 자료, 3주차 수업용)

제1장 알고리즘의 효율을 어떻게 비교하는가

1.1 점근 표기법의 의미

알고리즘의 효율은 보통 입력 크기 n이 커질 때 수행 시간이 얼마나 빠르게 늘어나는지로 비교한다. 빅오 표기법 O(f(n))은 충분히 큰 n에 대해 수행 시간이 f(n)의 상수배를 넘지 않는다는 상한을 뜻한다. 예를 들어 어떤 알고리즘의 연산 횟수가 3n² + 20n + 100이라면, n이 커질수록 n² 항이 전체를 지배하므로 O(n²)이라고 쓴다. 이 수업에서는 최악의 경우를 기준으로 말하되, 퀵 정렬처럼 평균과 최악이 크게 다른 알고리즘은 두 값을 함께 적는다.

빅오메가 Ω는 하한, 빅세타 Θ는 상한과 하한이 같은 차수일 때 쓰는 표기다. 시험에서는 "비교 기반 정렬의 하한은 Ω(n log n)이다"라는 문장을 자주 묻는데, 이는 원소 n개를 비교만으로 정렬하려면 가능한 순열 n!개를 구별해야 하고, 비교 한 번은 결과를 두 갈래로만 나누므로 결정 트리의 높이가 최소 log₂(n!)이 되어야 한다는 논증에서 나온다. 스털링 근사를 쓰면 log₂(n!)은 대략 n log₂ n - 1.44n이다.

1.2 이론과 실제 측정의 차이

점근 표기법은 상수와 낮은 차수의 항을 버리기 때문에 작은 입력에서는 순위가 뒤집히기도 한다. 지난 실습에서 원소 16개짜리 배열을 정렬했을 때 삽입 정렬이 병합 정렬보다 빨랐던 것이 대표적인 예다. 삽입 정렬은 함수 호출과 보조 배열 할당이 없고, 거의 정렬된 데이터에서는 비교 횟수가 n에 가깝게 줄어든다. 그래서 실무 라이브러리는 하이브리드 방식을 쓴다. Java의 Arrays.sort는 기본형 배열에 듀얼 피벗 퀵 정렬을, 객체 배열에 팀소트를 사용하며, 두 구현 모두 일정 길이 이하의 구간에서는 삽입 정렬로 전환한다.

캐시 효과도 무시할 수 없다. 배열을 앞에서부터 차례로 읽는 알고리즘은 CPU 캐시 라인(보통 64바이트)을 한 번 가져와 여러 원소를 연속으로 쓰기 때문에, 같은 O(n log n)이라도 포인터를 따라 메모리를 건너뛰는 알고리즘보다 몇 배 빠를 수 있다. 성능을 이야기할 때는 반드시 "어떤 입력에서, 어떤 환경으로 쟀는가"를 함께 적는 습관을 들이자.

제2장 비교 기반 정렬

2.1 단순 정렬: 선택, 버블, 삽입

선택 정렬은 남은 구간에서 가장 작은 원소를 찾아 맨 앞과 교환하는 과정을 n-1번 반복한다. 비교 횟수는 입력과 상관없이 항상 n(n-1)/2번이지만 교환은 최대 n-1번이라, 쓰기 비용이 큰 저장 장치에서는 오히려 장점이 된다. 버블 정렬은 인접한 두 원소를 비교해 순서가 틀리면 바꾸는 과정을 반복하며, 한 바퀴 동안 교환이 한 번도 없으면 조기 종료하도록 개선할 수 있다. 삽입 정렬은 카드를 손에 쥐고 한 장씩 알맞은 자리에 끼워 넣는 방식으로, 평균과 최악은 O(n²)이지만 이미 정렬된 입력에서는 O(n)이다.

세 알고리즘 모두 추가 메모리는 O(1)인 제자리 정렬이다. 안정성 측면에서는 버블 정렬과 삽입 정렬이 안정 정렬이고, 선택 정렬은 멀리 떨어진 원소끼리 교환하기 때문에 안정적이지 않다. 안정 정렬이란 키가 같은 원소들의 원래 상대 순서가 정렬 후에도 유지되는 정렬을 말한다. 예를 들어 학생 목록을 이름순으로 정렬한 뒤 학년순으로 다시 안정 정렬하면, 같은 학년 안에서는 이름순이 그대로 남는다.

2.2 병합 정렬

병합 정렬은 분할 정복의 교과서적인 예다. 배열을 절반으로 나누어 각각 재귀적으로 정렬한 다음, 정렬된 두 부분을 하나로 합친다. 합치는 단계는 두 부분의 맨 앞 원소를 비교해 작은 쪽을 결과에 옮기는 일을 반복하므로 선형 시간에 끝난다. 재귀 깊이가 log₂ n이고 각 깊이에서 전체 n개를 한 번씩 옮기므로 시간 복잡도는 최선, 평균, 최악 모두 O(n log n)이다.

단점은 배열 기반 구현에서 크기 n의 보조 배열이 필요하다는 점이다. 원소 100만 개의 int 배열이라면 약 4MB의 추가 메모리가 든다. 반면 연결 리스트에서는 포인터만 바꾸면 되므로 보조 배열 없이 병합할 수 있고, 데이터가 메모리에 다 올라가지 않는 외부 정렬에서도 병합 정렬이 기본 골격이 된다. 병합할 때 왼쪽 원소를 우선하면 안정 정렬이 된다는 점도 기억하자.

2.3 퀵 정렬

퀵 정렬은 피벗 하나를 고른 뒤 피벗보다 작은 원소는 왼쪽, 큰 원소는 오른쪽으로 보내는 분할을 하고, 양쪽 구간을 재귀적으로 정렬한다. 분할이 매번 절반 근처로 이루어지면 O(n log n)이지만, 이미 정렬된 배열에서 항상 첫 원소를 피벗으로 고르면 한쪽 구간이 비어 버려 O(n²)으로 떨어진다. 이를 막기 위해 무작위 피벗이나 처음, 중간, 끝 세 값의 중앙값을 피벗으로 쓰는 방법을 사용한다.

평균적으로는 병합 정렬보다 비교 횟수가 약 39% 많지만, 원소 이동이 적고 메모리를 연속으로 접근하기 때문에 실제로는 더 빠른 경우가 많다. 추가 메모리는 재귀 스택만큼인 평균 O(log n)이다. 최악의 경우 스택이 O(n)까지 깊어지는 것을 막으려면 더 작은 쪽 구간을 먼저 재귀 호출하고 큰 쪽은 반복문으로 처리하면 된다. 퀵 정렬은 일반적으로 안정 정렬이 아니다.

2.4 힙 정렬

힙 정렬은 배열을 최대 힙으로 만든 뒤 루트(최댓값)를 배열 끝과 교환하고 힙 크기를 하나 줄이는 과정을 반복한다. 상향식 힙 구성은 O(n)에 끝나고, 이후 n번의 삭제가 각각 O(log n)이므로 전체는 최악에도 O(n log n)이다. 추가 메모리가 O(1)이라는 점은 병합 정렬보다 낫지만, 부모와 자식 인덱스(i와 2i+1, 2i+2)를 오가며 메모리를 건너뛰기 때문에 캐시 효율은 퀵 정렬보다 떨어진다. C++ 표준 라이브러리의 인트로소트는 퀵 정렬의 재귀 깊이가 2·log₂ n을 넘으면 힙 정렬로 바꾸어 최악의 경우를 막는다.

2.5 정렬 알고리즘 비교 정리

시간 복잡도만 보면 병합 정렬, 힙 정렬, 퀵 정렬(평균)이 모두 O(n log n)이라 차이가 없어 보인다. 선택 기준은 대개 세 가지다. 첫째, 안정성이 필요하면 병합 정렬이나 팀소트를 쓴다. 둘째, 메모리가 빠듯하고 최악의 경우를 보장해야 하면 힙 정렬이 맞다. 셋째, 평균 속도가 가장 중요하고 입력이 무작위에 가깝다면 퀵 정렬이 보통 가장 빠르다. 실습 과제에서 원소 100만 개의 무작위 정수 배열을 정렬했을 때 우리 반 평균 측정값은 퀵 정렬 약 85ms, 병합 정렬 약 120ms, 힙 정렬 약 160ms였다. 같은 데이터를 미리 정렬해 두고 첫 원소 피벗 퀵 정렬을 돌리면 재귀가 너무 깊어져 스택 오버플로가 났다는 보고도 여러 건 있었다.

제3장 비교하지 않는 정렬

3.1 계수 정렬

계수 정렬은 키가 0부터 k까지의 작은 정수일 때 각 값의 등장 횟수를 세어 누적합으로 위치를 계산한다. 시간은 O(n + k), 메모리도 O(n + k)이다. 시험 점수 0점부터 100점까지 3만 명의 답안을 점수순으로 정렬하는 문제라면 k가 100에 불과하므로 비교 정렬보다 훨씬 빠르다. 반대로 키 범위가 32비트 정수 전체라면 카운트 배열만 수십억 칸이 필요하므로 쓸 수 없다. 누적합 배열을 뒤에서부터 채우면 안정 정렬이 된다.

3.2 기수 정렬

기수 정렬은 자릿수별로 안정 정렬(보통 계수 정렬)을 반복한다. 가장 낮은 자리부터 처리하는 LSD 방식은 d자리 수에 대해 O(d·(n + b))의 시간이 걸리며, b는 한 자리의 기수다. 예를 들어 32비트 정수를 8비트씩 끊어 b = 256으로 처리하면 네 번의 패스로 정렬이 끝난다. 자릿수 d가 상수로 고정되어 있다면 사실상 선형 시간이지만, 문자열처럼 길이가 제각각인 키에서는 가장 높은 자리부터 처리하는 MSD 방식을 쓴다.

제4장 탐색

4.1 순차 탐색과 이진 탐색

정렬되지 않은 배열에서 값을 찾으려면 처음부터 끝까지 하나씩 확인하는 순차 탐색밖에 없고, 평균 n/2번, 최악 n번 비교한다. 배열이 정렬되어 있다면 이진 탐색으로 매번 탐색 범위를 절반으로 줄일 수 있다. 원소 100만 개라면 최대 20번, 10억 개라도 최대 30번의 비교로 충분하다. 구현할 때 가장 흔한 실수는 중간 인덱스를 (low + high) / 2로 계산해 정수 오버플로가 나는 것이다. low + (high - low) / 2로 쓰면 이 문제를 피할 수 있으며, 실제로 Java 표준 라이브러리의 이진 탐색에서도 2006년에 이 버그가 보고되어 수정되었다.

이진 탐색은 "조건을 만족하는 첫 위치 찾기"로 일반화하면 활용 폭이 넓어진다. lower_bound는 값 x 이상이 처음 나오는 위치를, upper_bound는 x보다 큰 값이 처음 나오는 위치를 돌려주며, 두 값의 차이가 곧 x의 개수다. 정답이 단조성을 갖는 최적화 문제, 예를 들어 "하루 최대 작업량을 얼마로 정하면 마감 안에 끝낼 수 있는가" 같은 문제에도 매개변수 탐색이라는 이름으로 같은 아이디어를 쓴다.

4.2 이진 탐색 트리와 균형

이진 탐색 트리는 왼쪽 서브트리의 모든 키가 노드보다 작고 오른쪽 서브트리의 모든 키가 노드보다 큰 트리다. 탐색, 삽입, 삭제가 트리 높이 h에 비례하므로 균형이 잡혀 있으면 O(log n)이지만, 1, 2, 3, 4처럼 정렬된 순서로 삽입하면 한쪽으로만 길어진 연결 리스트가 되어 O(n)이 된다. AVL 트리는 모든 노드에서 좌우 높이 차이를 1 이하로 유지하고, 레드-블랙 트리는 색 규칙을 통해 가장 긴 경로가 가장 짧은 경로의 두 배를 넘지 않게 한다. Java의 TreeMap과 C++의 std::map은 레드-블랙 트리로 구현되어 있다.

4.3 해시를 이용한 탐색과의 비교

해시 테이블은 키를 해시 함수로 배열 인덱스에 대응시켜 평균 O(1)에 탐색한다. 이번 학기 자료구조 수업에서 다루는 해시 테이블은 메모리 안의 자료구조이며, 핵심 지표는 로드 팩터, 즉 저장된 원소 수를 버킷 수로 나눈 값이다. Java의 HashMap은 로드 팩터가 0.75를 넘으면 버킷 배열을 두 배로 늘리고 모든 원소를 다시 배치하며, 한 버킷에 원소가 8개 이상 몰리고 전체 버킷이 64개 이상이면 그 버킷을 연결 리스트에서 레드-블랙 트리로 바꾼다.

해시 테이블과 균형 이진 탐색 트리 중 무엇을 쓸지는 필요한 연산으로 결정한다. 키가 정확히 일치하는 값을 찾는 것만 필요하다면 해시 테이블이 빠르다. 하지만 "70점 이상 85점 이하인 학생" 같은 범위 질의, 최솟값과 최댓값, 정렬된 순서로 순회하기가 필요하다면 해시 테이블은 원소를 전부 훑어야 하므로 트리가 낫다. 또한 해시 테이블의 O(1)은 평균일 뿐이고, 악의적으로 충돌을 유도하는 입력이 들어오면 최악 O(n)까지 떨어질 수 있다는 점도 함께 기억하자.

4.4 실습 과제 안내

다음 주까지 정렬 알고리즘 네 가지(삽입, 병합, 퀵, 힙)를 직접 구현하고, 원소 수 1천, 1만, 10만, 100만 개에 대해 무작위 입력, 정렬된 입력, 역순 입력의 세 경우로 수행 시간을 측정해 표로 제출한다. 측정은 같은 입력으로 다섯 번 반복해 중앙값을 적고, JIT 워밍업의 영향을 줄이기 위해 첫 측정은 버린다. 보고서에는 이론적 복잡도와 측정 결과가 어긋나는 지점을 하나 이상 찾아 그 이유를 캐시, 재귀 깊이, 비교 횟수 가운데 무엇으로 설명할 수 있는지 서술한다.
