# 페이지 교체 알고리즘

> 출처: 한국어 위키백과 「페이지 교체 알고리즘」 (revision 42835065), CC BY-SA 4.0. 강의 자료용으로 일부 절을 생략하고 제목 형식을 바꿨다. 자세한 내용은 SOURCES.md 참고.

가상 메모리 관리를 위해 페이징을 사용하는 운영체제에서, 페이지 교체 알고리즘(page replacement algorithm)은 메모리 페이지를 할당해야 할 때 어떤 메모리 페이지를 페이지 아웃(스왑 아웃이라고도 함)하거나 디스크에 기록할지 결정한다. 페이지 교체는 요청된 페이지가 메모리에 없고(페이지 부재), 가용 페이지가 없거나 가용 페이지 수가 특정 임계값보다 낮아 할당을 만족할 수 없을 때 발생한다.

교체 대상으로 선택되어 페이지 아웃된 페이지가 다시 참조되면 페이지 인(디스크에서 읽어옴) 되어야 하며, 이 과정에서 I/O 완료를 기다려야 한다. 이것이 페이지 교체 알고리즘의 품질을 결정한다. 페이지 인을 기다리는 시간이 적을수록 더 좋은 알고리즘이다. 페이지 교체 알고리즘은 하드웨어가 제공하는 페이지 접근에 관한 제한된 정보를 바탕으로, 알고리즘 자체의 비용(주기억장치 및 프로세서 시간)과 균형을 맞추면서 전체 페이지 미스 횟수를 최소화하기 위해 어떤 페이지를 교체해야 할지 추측한다.

페이지 교체 문제는 최적의 결정론적 알고리즘이 알려져 있다는 점에서 경쟁 분석 관점의 전형적인 온라인 알고리즘 문제이다.

## 지역 교체 vs. 전역 교체

교체 알고리즘은 지역적일 수도 있고 전역적일 수도 있다.

프로세스에서 페이지 부재가 발생했을 때, 지역 페이지 교체 알고리즘은 해당 프로세스(또는 메모리 파티션을 공유하는 프로세스 그룹)에 속한 페이지 중에서 교체 대상을 선택한다. 전역 교체 알고리즘은 메모리에 있는 모든 페이지 중 하나를 자유롭게 선택할 수 있다.

지역 페이지 교체는 특정 프로세스나 프로세스 그룹에 할당될 페이지 수를 결정하는 일종의 메모리 파티셔닝을 전제로 한다. 가장 대중적인 파티셔닝 형태는 고정 파티셔닝과 워킹 세트 모델에 기반한 균형 세트 알고리즘이다. 지역 페이지 교체의 장점은 확장성이다. 각 프로세스가 독립적으로 페이지 부재를 처리할 수 있어 해당 프로세스에 대해 일관된 성능을 보장한다. 그러나 시스템 전체적인 관점에서는 전역 페이지 교체가 더 효율적이다.

## 페이지 교체 알고리즘

다양한 페이지 교체 알고리즘이 존재한다.

### 이론적으로 최적인 페이지 교체 알고리즘

이론적으로 최적인 페이지 교체 알고리즘(OPT, 투시적 교체 알고리즘, 또는 벨라디의 최적 페이지 교체 정책으로도 알려짐)은 다음과 같이 작동하는 알고리즘이다. 페이지를 스왑 인 해야 할 때, 운영체제는 다음 사용까지의 시간이 가장 멀리 남은 페이지를 스왑 아웃한다. 예를 들어, 0.4초 이내에 사용될 페이지보다는 향후 6초 동안 사용되지 않을 페이지를 스왑 아웃한다.

이 알고리즘은 범용 운영체제에서 구현될 수 없는데, 시스템에서 실행될 모든 소프트웨어를 미리 알고 그 메모리 참조 패턴을 정적으로 분석할 수 있거나 런타임 분석이 가능한 특정 범주의 애플리케이션인 경우를 제외하고는 페이지가 사용되기 전까지 얼마나 걸릴지 신뢰성 있게 계산하는 것이 불가능하기 때문이다. 이러한 한계에도 불구하고 최적에 가까운 성능을 제공할 수 있는 알고리즘들이 존재한다. 운영체제는 프로그램이 참조한 모든 페이지를 추적하고, 그 데이터를 사용하여 이후 실행 시 어떤 페이지를 스왑 인/아웃할지 결정한다. 이 알고리즘은 프로그램의 첫 실행 시에는 불가능하지만, 실행 시마다 메모리 참조 패턴이 비교적 일관된 경우 최적에 가까운 성능을 제공할 수 있다.

페이징 문제에 대한 분석은 온라인 알고리즘 분야에서도 수행되었다. 페이징 문제에 대한 무작위 온라인 알고리즘의 효율성은 분할 상환 분석을 사용하여 측정된다.

### 최근 미사용 (NRU)

최근 미사용(NRU, Not Recently Used) 페이지 교체 알고리즘은 최근에 사용된 페이지를 메모리에 유지하는 것을 선호하는 알고리즘이다. 이 알고리즘은 다음과 같은 원리로 작동한다. 페이지가 참조되면 해당 페이지에 참조 비트가 설정되어 참조되었음을 표시한다. 마찬가지로 페이지가 수정(기록)되면 수정 비트가 설정된다. 비트 설정은 보통 하드웨어에 의해 이루어지지만 소프트웨어 수준에서도 가능하다.

특정 고정 시간 간격마다 타이머 인터럽트가 발생하여 모든 페이지의 참조 비트를 해제하므로, 현재 타이머 간격 내에 참조된 페이지들만 참조 비트가 설정된 상태로 남는다. 페이지 교체가 필요할 때 운영체제는 페이지를 다음의 네 가지 클래스로 분류한다.

- 클래스 3: 참조됨, 수정됨

- 클래스 2: 참조됨, 수정되지 않음

- 클래스 1: 참조되지 않음, 수정됨

- 클래스 0: 참조되지 않음, 수정되지 않음

페이지가 수정되었으나 참조되지 않는 것이 불가능해 보일 수도 있지만, 이는 클래스 3 페이지의 참조 비트가 타이머 인터럽트에 의해 해제되었을 때 발생한다. NRU 알고리즘은 가장 낮은 카테고리에서 무작위로 페이지를 선택하여 제거한다. 즉, 위 네 가지 카테고리 중 참조되지 않고 수정되지 않은 페이지가 있다면 이를 먼저 교체한다. 이 알고리즘은 (최근 타이머 간격 내에) 수정되었으나 참조되지 않은 페이지가, 집중적으로 참조되고 있는 수정되지 않은 페이지보다 덜 중요하다는 점을 시사한다.

### 선입 선출 (FIFO)

가장 단순한 페이지 교체 알고리즘은 FIFO 알고리즘이다. 선입 선출(FIFO, First-In, First-Out) 페이지 교체 알고리즘은 운영체제 측의 관리 부담이 적은 저비용 알고리즘이다. 아이디어는 이름에서 알 수 있듯이 명확하다. 운영체제는 메모리에 있는 모든 페이지를 큐에 유지하며, 가장 최근에 들어온 페이지는 뒤에, 가장 오래된 페이지는 앞에 둔다. 페이지 교체가 필요할 때 큐의 맨 앞에 있는 페이지(가장 오래된 페이지)가 선택된다. FIFO는 저렴하고 직관적이지만 실제 응용 프로그램에서의 성능은 좋지 않다. 따라서 수정되지 않은 순수 형태로 사용되는 경우는 드물다. 이 알고리즘은 벨라디의 변이 현상을 겪는다.

단순히 말해, 페이지 부재 시 메모리에 가장 오래 머물렀던 프레임이 교체된다.

FIFO 페이지 교체 알고리즘은 일부 수정된 형태로 OpenVMS 운영체제에서 사용된다. 유효한 변환 테이블 참조가 있는 항목들을 제한적으로 건너뜀으로써 부분적인 2차 기회를 제공하며, 추가적으로 프로세스 워킹 세트에서 축출된 페이지들을 시스템 전체 풀로 이동시켜 아직 재사용되지 않았다면 복구할 수 있도록 한다.

### 2차 기회

FIFO 페이지 교체 알고리즘의 수정된 형태인 2차 기회(Second-chance) 페이지 교체 알고리즘은 적은 비용으로 FIFO보다 상대적으로 나은 성능을 보인다. FIFO처럼 큐의 맨 앞을 확인하지만, 즉시 페이지 아웃하는 대신 참조 비트가 설정되어 있는지 확인한다. 설정되어 있지 않으면 페이지를 스왑 아웃한다. 설정되어 있다면 참조 비트를 해제하고 페이지를 큐의 맨 뒤에 (마치 새 페이지인 것처럼) 삽입한 뒤 이 과정을 반복한다. 이는 원형 큐로 생각할 수도 있다. 모든 페이지의 참조 비트가 설정되어 있다면, 리스트의 첫 번째 페이지를 다시 만났을 때 해당 페이지의 참조 비트가 이미 해제된 상태이므로 스왑 아웃된다. 모든 페이지의 참조 비트가 해제된 상태라면 2차 기회 알고리즘은 순수 FIFO와 동일하게 작동한다.

이름에서 알 수 있듯이 2차 기회 알고리즘은 모든 페이지에 "2차 기회"를 준다. 참조된 적이 있는 오래된 페이지는 아마도 사용 중일 가능성이 높으므로, 참조된 적이 없는 새 페이지보다 먼저 스왑 아웃되어서는 안 된다는 논리다.

### 클럭 (Clock)

클럭(Clock) 알고리즘은 페이지를 리스트의 뒤로 계속 밀어낼 필요가 없기 때문에 2차 기회 알고리즘보다 효율적인 버전이지만, 2차 기회와 동일한 일반적 기능을 수행한다. 클럭 알고리즘은 메모리에 있는 페이지들의 원형 리스트를 유지하며, "시곗바늘"(반복자)은 리스트에서 마지막으로 검사된 페이지 프레임을 가리킨다. 페이지 부재가 발생하고 빈 프레임이 없으면 시곗바늘 위치의 R(참조) 비트를 검사한다. R이 0이면 "시곗바늘"이 가리키는 페이지 자리에 새 페이지를 넣고 바늘을 한 칸 전진시킨다. R이 1이면 R 비트를 0으로 지우고 바늘을 전진시키며 페이지가 교체될 때까지 이 과정을 반복한다. 이 알고리즘은 1969년 페르난도 J. 코바토에 의해 처음 기술되었다.

### 최근 최소 사용 (LRU)

최근 최소 사용(LRU, Least Recently Used) 페이지 교체 알고리즘은 이름은 NRU와 비슷하지만, NRU가 마지막 클럭 간격의 사용 여부만 보는 반면 LRU는 짧은 기간 동안의 페이지 사용 기록을 추적한다는 점에서 다르다. LRU는 지난 몇 번의 명령 동안 가장 집중적으로 사용된 페이지가 다음 몇 번의 명령 동안에도 집중적으로 사용될 가능성이 높다는 아이디어에 기반한다. LRU는 이론적으로 최적에 가까운 성능을 제공할 수 있지만(적응형 교체 캐시만큼 훌륭함), 실제 구현하기에는 비용이 많이 든다. 성능은 최대한 유지하면서 비용을 줄이려는 몇 가지 구현 방법이 존재한다.

가장 비용이 많이 드는 방법은 메모리에 있는 모든 페이지를 포함하는 연결 리스트를 사용하는 것이다. 리스트의 맨 뒤에는 최근에 가장 적게 사용된 페이지가, 맨 앞에는 최근에 가장 많이 사용된 페이지가 위치한다. 이 구현의 비용은 메모리 참조가 일어날 때마다 리스트의 항목을 이동시켜야 한다는 점에 있으며, 이는 매우 시간 소모적인 프로세스이다.

하드웨어 지원이 필요한 또 다른 방법은 다음과 같다. 하드웨어에 매 명령마다 증가하는 64비트 카운터가 있다고 가정하자. 페이지에 접근할 때마다 해당 페이지는 접근 당시의 카운터 값을 획득한다. 페이지 교체가 필요할 때 운영체제는 카운터 값이 가장 낮은 페이지를 선택하여 스왑 아웃한다.

구현 비용 때문에 이후 설명할 LRU와 유사하지만 더 저렴한 구현을 제공하는 알고리즘들을 고려할 수 있다.

LRU 알고리즘의 한 가지 중요한 장점은 완전한 통계적 분석이 가능하다는 점이다. 예를 들어, LRU는 OPT 알고리즘보다 N배 이상의 페이지 부재를 발생시키지 않는다는 것이 증명되었으며, 여기서 N은 관리되는 풀의 페이지 수에 비례한다.

반면 LRU의 약점은 상당히 일반적인 여러 참조 패턴에서 성능이 저하되는 경향이 있다는 것이다. 예를 들어, LRU 풀에 N개의 페이지가 있을 때 애플리케이션이 N+1개 페이지의 배열에 대해 루프를 실행하면 매 접근마다 페이지 부재가 발생한다. 대형 배열에 대한 루프는 흔하기 때문에, 이러한 상황에서 더 잘 작동하도록 LRU를 수정하려는 노력이 많이 이루어졌다. 제안된 많은 LRU 변형들은 루프 참조 패턴을 감지하여 최근 최대 사용(MRU)과 같은 적절한 교체 알고리즘으로 전환하려고 시도한다.

### 최저 빈도 사용 (NFU)

최저 빈도 사용(NFU, Not Frequently Used) 페이지 교체 알고리즘은 카운터가 필요하며, 모든 페이지는 초기에 0으로 설정된 자신만의 카운터를 가진다. 각 클럭 간격마다 해당 간격 내에 참조된 모든 페이지의 카운터가 1씩 증가한다. 사실상 카운터는 페이지가 얼마나 자주 사용되었는지를 추적한다. 따라서 필요할 때 카운터가 가장 낮은 페이지를 스왑 아웃할 수 있다.

NFU의 주요 문제는 사용 기간(time span)을 고려하지 않고 사용 빈도만 추적한다는 점이다. 따라서 다단계 컴파일러에서 첫 번째 단계 동안 집중적으로 사용되었지만 두 번째 단계에서는 필요 없는 페이지가, 두 번째 단계에서 비교적 적게 사용되는 페이지보다 카운터가 높아 우선적으로 유지되는 현상이 발생한다. 이는 저조한 성능으로 이어진다. 운영체제 부팅 시와 같은 다른 일반적인 시나리오에서도 NFU는 비슷하게 작동한다. 다행히 이와 유사하면서 더 나은 알고리즘인 에이징 알고리즘이 존재한다.

최저 빈도 사용 페이지 교체 알고리즘은 페이지 테이블에 널 포인터 값이 포함되어 있을 때 최근 최소 사용 페이지 교체 알고리즘보다 페이지 부재를 적게 발생시킨다.

### 에이징 (Aging)

에이징(Aging) 알고리즘은 NFU 알고리즘의 후손으로, 사용 기간을 인식할 수 있도록 수정된 것이다. 단순히 참조된 페이지의 카운터를 증가시켜 시간에 관계없이 동일한 비중을 두는 대신, 페이지의 참조 카운터를 먼저 오른쪽으로 시프트(2로 나눔)한 뒤 해당 이진수의 왼쪽에 참조 비트를 추가한다. 예를 들어, 지난 6번의 클럭 틱 동안 한 페이지의 참조 비트가 1,0,0,1,1,0이었다면 참조 카운터는 시간순으로 10000000, 01000000, 00100000, 10010000, 11001000, 01100100이 된다. 오래전의 페이지 참조보다 현재에 가까운 페이지 참조가 더 큰 영향을 미친다. 이를 통해 과거에 빈번하게 참조되었더라도 최근에 참조되지 않은 페이지보다, 최근에 참조된 페이지가 더 높은 우선순위를 갖게 된다. 따라서 스왑 아웃이 필요할 때 카운터가 가장 낮은 페이지를 선택한다.

에이징은 프로세서 정수의 비트 크기에 따라 최신 16/32번의 시간 간격 내 참조만 추적할 수 있다는 점에서 LRU와 다르다. 결과적으로 한 페이지는 9개 간격 전에 참조되었고 다른 페이지는 1000개 간격 전에 참조되었더라도 두 페이지의 참조 카운터가 모두 00000000일 수 있다. 일반적으로 지난 16번의 간격 내 사용량을 아는 것만으로도 어떤 페이지를 스왑 아웃할지 결정하는 데 충분하다. 따라서 에이징은 적절한 비용으로 최적에 가까운 성능을 제공할 수 있다.

## 워킹 세트

프로세스의 워킹 세트는 특정 시간 간격 동안 해당 프로세스가 사용할 것으로 예상되는 페이지의 집합이다.

"워킹 세트 모델"은 엄밀한 의미의 페이지 교체 알고리즘은 아니며, 사실 일종의 중기 스케줄러에 가깝다.
